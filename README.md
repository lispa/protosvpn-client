# ProtosVPN Client — development preview 0.1.2

## Единое desktop-окно

Стандартная рамка ОС отключена: ретро-корпус занимает всё окно. В заголовке доступны сворачивание, разворачивание/восстановление и выход. Заголовок используется для перетаскивания через штатный механизм Wails, изменение размера окна разрешено. Закрытие завершает приложение (профили в RAM теряются), это не сворачивание в трей. В браузерном preview собственные кнопки окна скрыты.

## Язык интерфейса

По умолчанию используется язык системы: русский для русской локали, английский для остальных. В настройках доступен выбор «Системный / Русский / English». Смена применяется без перезапуска, выбор сохраняется локально отдельно от VPN-конфигураций. В Windows используется язык интерфейса пользователя ОС, в Linux — переменные локали окружения. В браузерном preview используется язык браузера. Названия и содержимое профилей не переводятся.

Windows/Linux desktop-клиент к существующим VPN-серверам. UI: Wails + Go + React/TypeScript. Визуальное направление — одобренный вариант 03: читаемый ретро-интерфейс в духе Winamp, не копия плеера.

## Границы этой версии

Это первый рабочий этап **импорта и управления профилями**, а не готовый VPN. Пока не интегрированы OpenVPN/sing-box, привилегированная служба, TUN, маршруты, DNS, kill switch и хранилище учётных данных ОС. Приложение **не меняет сеть и не подключается к серверам**. Кнопка подключения недоступна; вымышленные скорости/пинги/защищённый DNS не показываются.

Профили и конфигурации находятся **только в памяти текущего процесса**. При закрытии приложения исчезают. Это осознанное ограничение до интеграции защищённого хранилища. Перезагрузка страницы preview не завершает Go-процесс, поэтому сама по себе не удаляет серверную RAM. В локальные настройки интерфейса нельзя сохранять ключи, сертификаты или VLESS-ссылки.

## Поддерживаемый ввод

- VLESS: вставка `vless://` URI, локальная синтаксическая проверка и извлечение метаданных. Успешный импорт не подтверждает работоспособность сервера или транспорта.
- OpenVPN: самодостаточный `.ovpn` в поддерживаемом безопасном подмножестве. Внешние файлы ключей/сертификатов, скрипты, плагины, include и опасные файловые/management-директивы не выполняются и не принимаются. Полный список — в документации импортера `internal/client/`.
- Сертификаты не проходят криптографическую проверку цепочки на этом этапе. Их валидность будет проверяться VPN-движком при реальном подключении.

Не публикуйте настоящие `.ovpn`, ключи, UUID, ссылки подписок или пароли в issue/чатах и Git. Метаданные/ошибки/диагностика не должны возвращать исходную конфигурацию. В тестах используются только синтетические данные и зарезервированные адреса.

## Запуск проверяемого preview на Linux

Требуются Go и Node.js/npm. Go SDK, использованный при разработке: `/home/hermes/.local/toolchains/go/bin/go`.

```sh
cd frontend
npm ci
npm run build
cd ..
go run ./cmd/preview
```

Открыть `http://127.0.0.1:18761`. Preview слушает **только loopback** и использует ту же Go-логику/API, что desktop-оболочка. Это браузерный режим разработки, не фоновая VPN-служба. Не меняйте bind на публичный адрес и не открывайте API в интернет.

Для Vite-разработки запустите Go preview и отдельно `cd frontend && npm run dev`; конфигурация proxy направляет локальные `/api` к Go.

## Desktop-сборки

Зафиксированный Wails: `v2.17.1`. Требуется предварительная сборка `frontend/dist`.

```sh
go install github.com/wailsapp/wails/v2/cmd/wails@v2.17.1
# Windows x86_64, cross-compile. WebView2 требуется на целевой Windows.
wails build -platform windows/amd64 -s -skipbindings -tags desktop -trimpath -webview2 error
# Linux x86_64: GTK3 + WebKitGTK4.1, pkg-config и C toolchain.
wails build -platform linux/amd64 -s -skipbindings -tags desktop,webkit2_41 -trimpath
```

`-webview2 error` не запускает скрытую установку WebView2. Если runtime отсутствует, установите официальный Microsoft Edge WebView2 Runtime: https://developer.microsoft.com/en-us/microsoft-edge/webview2/ .

Сборки являются неподписанными development preview, не финальными установщиками. Windows может показать SmartScreen. Наличие `.exe` подтверждает cross-compilation, **не** тестирование работы на настоящей Windows.

Для Linux используется изолированный Docker builder (`build/linux.Dockerfile`, Ubuntu 24.04), чтобы не устанавливать GTK/WebKit и не обновлять пакеты на хосте. Нативная Linux-сборка требует соответствующих runtime-библиотек и графической сессии; поддержка всех дистрибутивов не заявляется. Отключение WebKit sandbox разрешается только для изолированного headless smoke-test контейнера, не для обычного запуска приложения.

## Проверки

```sh
go test -race ./internal/client/...
go test .
cd frontend && npm test && npm run build
```

Дополнительно выполняются интеграционные браузерные тесты против настоящего Go API: импорт, выделение, переименование, удаление, ошибки, отсутствие секретов в публичном состоянии и честный отказ подключения. HTTP-защита проверяет локальные Host/Origin и bootstrap CSRF-токен; это не замена будущему контролю доступа к привилегированной службе.

## Следующий этап

5. Второе ядро/ОС, подпись/обновления/установщик после проверенного сетевого MVP.
